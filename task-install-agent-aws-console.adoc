= Distribuisci un agente Console in AWS dalla NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Distribuisci un agente Console in AWS senza uscire da NetApp Console, così puoi iniziare a gestire le tue risorse AWS e i servizi dati.

La distribuzione di un agente Console in AWS avvia un'istanza EC2 che esegue Linux e il software dell'agente Console in una VPC a tua scelta.

.Prima di iniziare
* link:concept-agent-install-options.html#agent-console-deploy["Scopri quando effettuare il deployment dalla Console"].
* Revisionelink:reference-limitations.html["Limitazioni dell'agente della console"] .

== Passaggio 1: Configura la rete per distribuire un agente Console in AWS

Assicurati che la posizione di rete in cui intendi distribuire il Console agent soddisfi i seguenti requisiti. Questi requisiti consentono al Console agent di gestire risorse e processi nel tuo cloud ibrido.

VPC e sottorete:: Quando si crea l'agente Console, è necessario specificare la VPC e la subnet in cui deve risiedere.


Connessioni alle reti di destinazione:: L'agente Console richiede una connessione di rete alla posizione in cui si prevede di creare e gestire i sistemi.  Ad esempio, la rete in cui intendi creare sistemi Cloud Volumes ONTAP o un sistema di archiviazione nel tuo ambiente locale.


Accesso a Internet in uscita:: La posizione di rete in cui si distribuisce l'agente Console deve disporre di una connessione Internet in uscita per contattare endpoint specifici.


Endpoint contattati dall'agente della console:: L'agente della console necessita di accesso a Internet in uscita per contattare i seguenti endpoint per gestire risorse e processi all'interno dell'ambiente cloud pubblico per le operazioni quotidiane.
+
--
Gli endpoint elencati di seguito sono tutti voci CNAME.

Endpoint contattati dalla console NetApp:: Quando si utilizza l'applicazione SaaS Console NetApp basata sul web, questa si connette a diversi endpoint per completare le attività di gestione dei dati. Ciò include gli endpoint contattati per distribuire l'agente Console dalla Console stessa.

Server proxy:: NetApp supporta sia configurazioni proxy esplicite che trasparenti.  Se si utilizza un proxy trasparente, è necessario fornire solo il certificato per il server proxy.  Se si utilizza un proxy esplicito, saranno necessari anche l'indirizzo IP e le credenziali.
+
--
* indirizzo IP
* Credenziali
* Certificato HTTPS


--


porti:: Non c'è traffico in entrata verso l'agente della Console, a meno che non venga avviato dall'utente o utilizzato come proxy per inviare AutoSupport messaggi da Cloud Volumes ONTAP al supporto NetApp.
+
--
* HTTP (80) e HTTPS (443) forniscono l'accesso all'interfaccia utente locale, che utilizzerai in rare circostanze.
* SSH (22) è necessario solo se è necessario connettersi all'host per la risoluzione dei problemi.
* Le connessioni in ingresso sulla porta 3128 sono necessarie se si distribuiscono sistemi Cloud Volumes ONTAP in una subnet in cui non è disponibile una connessione Internet in uscita.
+
Se i sistemi Cloud Volumes ONTAP non dispongono di una connessione Internet in uscita per inviare messaggi AutoSupport , la Console configura automaticamente tali sistemi per utilizzare un server proxy incluso nell'agente della Console.  L'unico requisito è assicurarsi che il gruppo di sicurezza dell'agente Console consenta connessioni in entrata sulla porta 3128.  Sarà necessario aprire questa porta dopo aver distribuito l'agente Console.



--

+
--
Sarà necessario implementare questo requisito di rete dopo aver creato l'agente Console.

[[step-2-set-up-aws-permissions-to-deploy-the-console-agent]]
[[aws-permissions-agent]]
== Passaggio 2: Configura le autorizzazioni AWS per distribuire l'agente Console

Concedi alla Console solo le autorizzazioni AWS necessarie per distribuire l'agente della Console nella tua VPC, in base al metodo di autenticazione scelto.

Scegli uno di questi metodi di autenticazione e configura solo ciò che richiede:

[cols="1a,2a,2a"]
|===
| Metodo | Cosa fa | Cosa configuri 


 a| 
*Crea un ruolo per me*
 a| 
La Console apre AWS CloudFormation Quick Create, che crea il ruolo di distribuzione che la Console assume.
 a| 
Autorizzazioni per l'identità AWS che invia lo stack.



 a| 
*Assumi il ruolo*
 a| 
La Console assume un ruolo IAM esistente nel tuo account.
 a| 
Una politica e un ruolo IAM.



 a| 
*chiavi AWS*
 a| 
La Console utilizza una chiave di accesso AWS e una chiave segreta.
 a| 
Una policy e un utente IAM.

|===
Con le opzioni *Crea ruolo per me* e *Assumi ruolo*, la Console assume un ruolo IAM, denominato *ruolo di distribuzione*, per distribuire l'agente della Console. Dopo la distribuzione, l'agente della Console utilizza un ruolo IAM separato collegato alla sua istanza EC2, denominato *ruolo agente*. Per impostazione predefinita, la Console crea automaticamente il ruolo agente per te. link:#aws-agent-role["Scopri come utilizzare il tuo ruolo di agente"].



[[set-up-permissions-for-create-role-for-me-cloudformation-quick-create]]
[[aws-permissions-quick-create]]
=== Configura le autorizzazioni per Crea ruolo per me (CloudFormation Quick Create)

Utilizza un'identità AWS in grado di creare lo stack CloudFormation e il ruolo di distribuzione, in modo che lo stack si completi senza errori di autorizzazione.

L'identità che invia lo stack Quick Create di CloudFormation necessita di autorizzazioni di amministratore o delle seguenti autorizzazioni minime. Queste autorizzazioni consentono a CloudFormation di creare il ruolo di distribuzione. Non sono le autorizzazioni del ruolo dell'agente.

[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "CloudFormationStack",
      "Effect": "Allow",
      "Action": [
        "cloudformation:CreateStack",
        "cloudformation:DeleteStack",
        "cloudformation:DescribeStacks",
        "cloudformation:DescribeStackEvents",
        "cloudformation:GetTemplateSummary",
        "iam:CreateRole",
        "iam:DeleteRole",
        "iam:GetRole",
        "iam:PutRolePolicy",
        "iam:DeleteRolePolicy",
        "iam:GetRolePolicy",
        "iam:PassRole",
        "lambda:CreateFunction",
        "lambda:DeleteFunction",
        "lambda:GetFunction",
        "lambda:InvokeFunction"
      ],
      "Resource": "*"
    }
  ]
}
----


[[set-up-permissions-for-assume-role-or-aws-keys]]
[[aws-permissions-assume-role-keys]]
=== Configura le autorizzazioni per Assume role o le chiavi AWS

Se scegli *Assume role* o *AWS keys*, crea una policy con solo le autorizzazioni necessarie per distribuire l'agente di Console e associala al ruolo o all'utente che Console utilizza.

Se necessario, è possibile limitare la policy IAM utilizzando l'IAM `Condition` elemento. https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_condition.html["Documentazione AWS: Elemento Condizione"^]

.Passi
. Vai alla console AWS IAM.
. Selezionare *Criteri > Crea criterio*.
. Selezionare *JSON*.
. Copia e incolla la seguente policy:
+
Questa policy contiene solo le autorizzazioni necessarie per avviare l'agente della Console in AWS dalla Console. link:reference-permissions-aws.html["Visualizza le autorizzazioni del ruolo dell'agente"].

+
[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "iam:CreateRole",
        "iam:DeleteRole",
        "iam:PutRolePolicy",
        "iam:CreateInstanceProfile",
        "iam:DeleteRolePolicy",
        "iam:AddRoleToInstanceProfile",
        "iam:RemoveRoleFromInstanceProfile",
        "iam:DeleteInstanceProfile",
        "iam:PassRole",
        "iam:ListRoles",
        "ec2:DescribeInstanceStatus",
        "ec2:RunInstances",
        "ec2:ModifyInstanceAttribute",
        "ec2:CreateSecurityGroup",
        "ec2:DeleteSecurityGroup",
        "ec2:DescribeSecurityGroups",
        "ec2:RevokeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupIngress",
        "ec2:RevokeSecurityGroupIngress",
        "ec2:CreateNetworkInterface",
        "ec2:DescribeNetworkInterfaces",
        "ec2:DeleteNetworkInterface",
        "ec2:ModifyNetworkInterfaceAttribute",
        "ec2:DescribeSubnets",
        "ec2:DescribeVpcs",
        "ec2:DescribeDhcpOptions",
        "ec2:DescribeKeyPairs",
        "ec2:DescribeRegions",
        "ec2:DescribeInstances",
        "ec2:CreateTags",
        "ec2:DescribeImages",
        "ec2:DescribeAvailabilityZones",
        "ec2:DescribeLaunchTemplates",
        "ec2:CreateLaunchTemplate",
        "cloudformation:CreateStack",
        "cloudformation:DeleteStack",
        "cloudformation:DescribeStacks",
        "cloudformation:DescribeStackEvents",
        "cloudformation:ValidateTemplate",
        "ec2:AssociateIamInstanceProfile",
        "ec2:DescribeIamInstanceProfileAssociations",
        "ec2:DisassociateIamInstanceProfile",
        "iam:GetRole",
        "iam:TagRole",
        "kms:ListAliases",
        "cloudformation:ListStacks"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "ec2:TerminateInstances"
      ],
      "Condition": {
        "StringLike": {
          "ec2:ResourceTag/OCCMInstance": "*"
        }
      },
      "Resource": [
        "arn:aws:ec2:*:*:instance/*"
      ]
    }
  ]
}
----
. Selezionare *Avanti* e aggiungere tag, se necessario.
. Selezionare *Avanti* e immettere un nome e una descrizione.
. Selezionare *Crea policy*.
. È possibile associare il criterio a un ruolo IAM che la Console può assumere oppure a un utente IAM in modo da poter fornire alla Console le chiavi di accesso:
+
** *Assumi il ruolo*: Configura un ruolo IAM che la Console può assumere:
+
... Vai alla console AWS IAM nell'account di destinazione.
... In Gestione accessi, seleziona *Ruoli > Crea ruolo* e segui i passaggi per creare il ruolo.
... In *Tipo di entità attendibile*, seleziona *Account AWS*.
... Seleziona *Un altro account AWS* e inserisci l'ID dell'account SaaS della console: 952013314444
... Seleziona la policy creata nella sezione precedente.
... Dopo aver creato il ruolo, copia l'ARN del ruolo in modo da poterlo incollare nella Console quando crei l'agente della Console.


** *Chiavi AWS*: Configura le autorizzazioni per un utente IAM in modo da poter fornire alla Console le chiavi di accesso:
+
... Dalla console AWS IAM, seleziona *Utenti* e poi seleziona il nome utente.
... Seleziona *Aggiungi autorizzazioni > Allega direttamente i criteri esistenti*.
... Seleziona la policy che hai creato.
... Selezionare *Avanti* e quindi *Aggiungi autorizzazioni*.
... Assicurati di disporre della chiave di accesso e della chiave segreta per l'utente IAM.






.Risultato
Ora disponi di un ruolo di distribuzione o di un utente IAM con le autorizzazioni necessarie. Quando distribuisci l'agente Console, devi fornire l'ARN del ruolo o le chiavi di accesso.



[[step-3-set-up-your-own-iam-role-for-the-console-agent-optional]]
[[aws-agent-role]]
== Passaggio 3: Configura il tuo ruolo IAM per l'agente di Console (facoltativo)

Crea il tuo ruolo agente se vuoi selezionarlo invece del ruolo che la Console crea per impostazione predefinita. Crea il ruolo prima di distribuire l'agente della Console.

.Passi
. Accedi alla console AWS e vai al servizio IAM.
. Crea una policy:
+
.. Selezionare *Criteri > Crea criterio*.
.. Seleziona *JSON* e copia e incolla il contenuto dellink:reference-permissions-aws.html["Criterio IAM per l'agente della console"] .
.. Completare i passaggi rimanenti per creare la policy.
+
Per le regioni standard, le autorizzazioni sono distribuite su due policy.  Sono necessarie due policy a causa del limite massimo di dimensione dei caratteri per le policy gestite in AWS. link:reference-permissions-aws.html["Scopri di più sui criteri IAM per l'agente della console"] .



. Crea un ruolo IAM:
+
.. Selezionare *Ruoli > Crea ruolo*.
.. Selezionare *Servizio AWS > EC2*.
.. Aggiungi autorizzazioni allegando la policy appena creata.
.. Completa i passaggi rimanenti per creare il ruolo.




.Risultato
Ora hai un ruolo dell'agente che puoi selezionare in *Dettagli di distribuzione dell'agente* quando distribuisci l'agente Console.



[[step-4-deploy-the-console-agent]]
== Passaggio 4: Distribuisci l'agente Console

Inserisci i dettagli di autenticazione, implementazione, rete e gruppo di sicurezza in modo che Console avvii l'agente di Console nella tua VPC.

.Informazioni su questo compito
* La creazione dell'agente Console dalla Console distribuisce un'istanza EC2 in AWS utilizzando una configurazione predefinita.  Non passare a un'istanza EC2 più piccola con meno CPU o meno RAM dopo aver creato l'agente Console. link:reference-agent-default-config.html["Scopri la configurazione predefinita per l'agente Console"] .
* Per impostazione predefinita, la Console crea il ruolo agente e il relativo profilo. Se fornisci un ruolo agente personalizzato, assicurati di aggiornarlo man mano che nelle versioni future vengono aggiunte nuove autorizzazioni. link:reference-permissions-aws.html["Scopri di più sulla policy IAM per l'agente della console"].


.Prima di iniziare
Dovresti avere quanto segue:

* Un metodo di autenticazione AWS: *Crea ruolo per me*, *Assumi ruolo* o *Chiavi AWS*.
* Una VPC e una subnet che soddisfano i requisiti di rete.
* Una coppia di chiavi per l'istanza EC2.
* Dettagli su un server proxy, se è necessario un proxy per l'accesso a Internet dall'agente della console.
* Completato link:#networking-aws-agent["Passo 1"].
* Completato link:#aws-permissions-agent["Passo 2"].


.Passi
. Selezionare *Amministrazione > Agenti*.
. Nella pagina *Panoramica*, selezionare *Distribuisci agente > AWS*.
. Nella sezione *Credenziali AWS per la distribuzione dell'agente*, scegli uno dei seguenti metodi di autenticazione:
+
** *Crea un ruolo per me*:
+
... Seleziona la tua regione AWS e inserisci l'ID del tuo account AWS. Facoltativamente, puoi inserire un ID esterno.
... Seleziona *Open CloudFormation Quick Create*.
... In AWS, accetta i termini e seleziona *Crea stack*.
... Quando AWS termina la creazione del ruolo, torna alla Console e conferma il ruolo.


** *Assumi il ruolo*: Inserisci l'ARN del ruolo IAM e seleziona *Convalida le credenziali*.
** *Chiavi AWS*: Inserisci la chiave di accesso e la chiave segreta, quindi seleziona *Convalida credenziali*.


. Nella sezione *Dettagli di distribuzione dell'agente*, fornisci i dettagli dell'agente Console.
+
** Inserisci un nome.
** Aggiungi tag personalizzati (metadati).
** Scegli se vuoi che la Console crei il ruolo dell'agente oppure seleziona un ruolo dell'agente che link:#aws-agent-role["configura da solo"].
** Scegliere se si desidera crittografare i dischi EBS dell'agente Console.  È possibile utilizzare la chiave di crittografia predefinita oppure una chiave personalizzata.


. Nella sezione *Configurazione di rete*, specifica una VPC, una subnet e una coppia di chiavi per l'agente Console, scegli se abilitare un indirizzo IP pubblico e, facoltativamente, specifica una configurazione proxy.
+
Assicurati di disporre della coppia di chiavi corretta per accedere alla macchina virtuale dell'agente Console.  Senza una coppia di chiavi non è possibile accedervi.

. Nella sezione *Gruppo di sicurezza*, scegli se creare un nuovo gruppo di sicurezza o selezionare un gruppo di sicurezza esistente che consenta le regole inbound e outbound richieste.
+
link:reference-ports-aws.html["Visualizza le regole del gruppo di sicurezza per AWS"] .



. Rivedi le tue selezioni per verificare che la configurazione sia corretta.
+
.. La check box *Convalida configurazione agente* è selezionata per impostazione predefinita per consentire alla Console di convalidare i requisiti di connettività di rete durante la distribuzione. Se la Console non riesce a distribuire l'agente, fornisce un report per aiutarti nella risoluzione dei problemi. Se la distribuzione ha esito positivo, non viene fornito alcun report.


+
[NOTE]
====
** Se si utilizza ancora la link:reference-networking-saas-console-previous.html["punti finali precedenti"] utilizzata per gli aggiornamenti dell'agente, la convalida fallisce con un errore. Per evitarlo, deselezionare la check box per saltare il controllo di convalida.
** Durante l'installazione, NetApp verifica che l'host dell'agente disponga di almeno l'80% dello spazio su disco totale disponibile, che include 48 GB in `/opt` e 32 GB in `/var` (80 GB totali). Dopo l'installazione, è necessario che rimanga disponibile almeno il 20% dello spazio su disco totale, che include 12 GB in `/opt` e 8 GB in `/var` (20 GB totali).


====
. Selezionare *Aggiungi*.
+
La Console distribuisce l'agente della Console in circa 10 minuti. Rimani sulla pagina fino al completamento del processo.



.Risultato
Una volta completato il processo, l'agente della Console sarà disponibile per l'uso dalla Console.

Se disponi di bucket Amazon S3 nello stesso account AWS in cui hai creato l'agente della console, vedrai apparire automaticamente un ambiente di lavoro Amazon S3 nella pagina *Sistemi*. https://docs.netapp.com/us-en/storage-management-s3-storage/index.html["Scopri come gestire i bucket S3 dalla NetApp Console"^]

== Risoluzione dei problemi relativi a una distribuzione non riuscita dell'agente Console

Utilizza il report di distribuzione per individuare cosa ha bloccato la distribuzione dell'agente Console, quindi riprova.

La Console fornisce un report solo se è stata selezionata la check box *Validate agent configuration*. Se la distribuzione riesce, non viene generato alcun report.

.Passi
. Nella finestra di dialogo *Distribuzione agente non riuscita*, seleziona *Scarica report*.
+
Console scarica un file PDF contenente il report di convalida.

. Esamina il report e risolvi i problemi che elenca.
. Nella finestra di dialogo, seleziona *Start over* e quindi completa di nuovo la distribuzione.
+
Per riprovare, devi ricominciare l'intero processo da capo.



link:task-troubleshoot-agent.html#troubleshoot-installation["Scopri come risolvere i problemi di installazione."]
