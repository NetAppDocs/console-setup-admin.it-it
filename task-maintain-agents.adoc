= Mantieni le istanze di macchine virtuali dell'agente NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Gestisci le VM degli agenti di NetApp Console applicando gli aggiornamenti di sicurezza del sistema operativo agli agenti installati manualmente, rispondendo agli avvisi relativi a CPU, RAM e spazio su disco e ridimensionando o arrestando e riavviando le VM quando necessario.

Quando si installa manualmente un agente Console, la manutenzione del sistema operativo sull'host dell'agente è responsabilità del cliente. Ad esempio, il cliente deve applicare gli aggiornamenti di sicurezza al sistema operativo sull'host dell'agente seguendo le procedure standard aziendali per la distribuzione del sistema operativo.

Se una VM agente risulta sottodimensionata o presenta problemi di prestazioni, devi intraprendere le azioni appropriate per potenziare le risorse della VM.


NOTE: Se hai installato l'agente in vCenter, usa il tool di manutenzione di Console per ridimensionare l'istanza di macchina virtuale. link:task-agent-vm-config.html["Scopri come eseguire la manutenzione di una VM agente in vCenter"^].



[[apply-operating-system-updates-to-the-manually-installed-agent-hosts]]
== Applica gli aggiornamenti del sistema operativo agli host dell'agente installato manualmente

Applica le patch di sicurezza del sistema operativo senza interrompere i servizi host dell'agente.

Per mantenere la compatibilità con le configurazioni supportate, è consigliabile impedire l'aggiornamento di Docker o Podman durante le normali procedure di applicazione delle patch del sistema operativo. È possibile farlo escludendo temporaneamente Docker o Podman dagli aggiornamenti oppure configurando in modo permanente il gestore di pacchetti in modo che ignori gli aggiornamenti di Docker o Podman.

Di seguito sono riportati alcuni esempi su come escludere gli aggiornamenti di Docker o Podman per diverse distribuzioni Linux. Consulta la documentazione della tua distribuzione Linux per le istruzioni più aggiornate su come escludere i pacchetti dagli aggiornamenti.

.Esempio di Podman
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Esempio Docker
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resizing-the-vm-or-instance-type]]
== Ridimensionamento della macchina virtuale o del tipo di istanza

Se si crea un agente Console dalla Console, questo distribuisce un'istanza VM nel provider cloud con una configurazione predefinita.  Dopo aver creato l'agente, non passare a un'istanza VM più piccola con meno CPU o RAM.

Se ricevi notifiche che indicano che la tua VM agente non dispone di risorse sufficienti, valuta la possibilità di passare a un'istanza di macchine virtuali più grande con più CPU o RAM per garantire prestazioni ottimali.


NOTE: Se hai installato l'agente in vCenter, usa lo strumento di manutenzione di Console per ridimensionare l'istanza di macchina virtuale. link:task-agent-vm-config.html["Scopri come ridimensionare la VM dell'agente in VCenter"^].

link:reference-agent-default-config.html["Scopri la configurazione predefinita per l'agente"] .

Se devi aumentare la CPU o la RAM della VM dell'agente, segui le istruzioni fornite dal tuo cloud provider o dalla piattaforma di virtualizzazione on-premises per ridimensionare l'istanza di macchina virtuale. NetApp consiglia di raddoppiare l'allocazione corrente di CPU e RAM per garantire prestazioni ottimali. La tabella seguente mostra i livelli di dimensionamento consigliati, in cui ogni livello raddoppia la CPU e la RAM del livello precedente.

[cols="1,1,1"]
|===
| Livello | CPU (core o vCPU) | Memoria RAM 


| Minimo | 8 | 32 GB 


| Medio | 16 | 64 GB 


| Grande | 32 | 128 GB 
|===

== Monitorare l'agente

La console ti avvisa quando la macchina virtuale dell'agente non è integro, compresi problemi di spazio su disco, RAM e CPU.  Monitora queste notifiche nel Centro notifiche all'interno della Console oppure configura le notifiche e-mail.  È normale che si verifichino occasionalmente aumenti dello spazio su disco, della memoria o dell'utilizzo della CPU, ma se ciò accade frequentemente, è opportuno adottare misure per risolverlo.

Ad esempio, la Console ti avvisa quando una risorsa agente (CPU, RAM o spazio su disco) supera il 90% della sua capacità totale per 30 minuti consecutivi.  Successivamente, se l'utilizzo delle risorse scende al di sotto di tale soglia, la notifica viene visualizzata come risolta (verde) nel Centro notifiche.


NOTE: Collabora con il supporto NetApp se hai domande sulla modifica della tua VM agente.

== Connettiti alla VM Linux

Se devi connetterti alla VM Linux su cui è in esecuzione l'agente, utilizza le opzioni di connettività del tuo provider cloud.

AWS:: Quando si crea l'istanza dell'agente in AWS, fornire una chiave di accesso AWS e una chiave segreta.  È possibile utilizzare questa coppia di chiavi per connettersi tramite SSH all'istanza.  Utilizzare il nome utente 'ubuntu' per l'istanza EC2 Linux.  Per gli agenti creati prima di maggio 2023, utilizzare il nome utente 'ec2-user'.
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["Documentazione AWS: connettiti alla tua istanza Linux"^]

--
Azzurro:: Quando si crea la macchina virtuale dell'agente in Azure, si specifica un nome utente e si sceglie di autenticarsi con una password o una chiave pubblica SSH.  Utilizza il metodo di autenticazione scelto per connetterti alla VM.
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Documentazione di Azure: accesso SSH alla macchina virtuale"^]

--
Google Cloud:: Non è possibile specificare un metodo di autenticazione quando si crea un agente in Google Cloud.  Tuttavia, puoi connetterti all'istanza della VM Linux tramite Google Cloud Console o Google Cloud CLI (gcloud).
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud Docs: connessione alle VM Linux"^]
