[[apply-operating-system-updates-to-agent-hosts]]
== Applica gli aggiornamenti del sistema operativo agli host degli agenti

Applica gli aggiornamenti di sicurezza al sistema operativo e ai pacchetti associati sull'host dell'agente in modo che l'host rimanga protetto.

Questa è una tua responsabilità come cliente. Il software dell'agente Console può aggiornarsi autonomamente, ma non aggiorna il sistema operativo o i pacchetti associati.


NOTE: Se hai distribuito l'agente Console in vCenter utilizzando un file OVA, il sistema operativo fa parte dell'immagine dell'agente. link:task-upgrade-agent.html#upgrade-a-vcenter-deployed-console-agent-using-an-iso["Aggiorna l'agente utilizzando un'immagine ISO"^] per aggiornare il sistema operativo.

Segui le procedure standard della tua azienda per la distribuzione del sistema operativo. Non è necessario interrompere i servizi dell'agente host quando applichi le patch di sicurezza del sistema operativo.

Sugli agenti che non hai distribuito da un file OVA, evita di aggiornare Docker o Podman durante le normali procedure di applicazione delle patch del sistema operativo per mantenere la compatibilità con le configurazioni supportate. Puoi farlo escludendo temporaneamente Docker o Podman durante gli aggiornamenti oppure configurando in modo permanente il gestore di pacchetti in modo che ignori gli aggiornamenti di Docker o Podman.

Di seguito sono riportati alcuni esempi su come escludere gli aggiornamenti di Docker o Podman per diverse distribuzioni Linux. Consulta la documentazione della tua distribuzione Linux per le istruzioni più aggiornate su come escludere i pacchetti dagli aggiornamenti.

.Esempio di Podman
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Esempio Docker
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resize-the-vm-or-instance-type]]
== Ridimensiona la macchina virtuale o il tipo di istanza

Aumenta la CPU o la RAM di una VM dell'agente con risorse insufficienti, in modo che l'agente continui a funzionare correttamente.

Se crei un agente Console dalla Console, distribuisce un'istanza di macchina virtuale nel tuo cloud provider con una configurazione predefinita. link:reference-agent-default-config.html["Scopri di più sulle impostazioni predefinite dell'agente"]. Dopo aver creato l'agente, non passare a un'istanza di macchina virtuale più piccola con meno CPU o RAM.

Se ricevi notifiche che indicano che la tua VM agente non dispone di risorse sufficienti, valuta la possibilità di passare a un'istanza di macchine virtuali più grande con più CPU o RAM.


NOTE: Se hai installato l'agente in vCenter, usa il tool di manutenzione di Console per ridimensionare l'istanza di macchina virtuale. link:task-agent-vm-config.html["Scopri come ridimensionare la VM dell'agente in vCenter"^].

Se devi aumentare la CPU o la RAM della VM dell'agente, segui le istruzioni fornite dal tuo cloud provider o dalla piattaforma di virtualizzazione on-premises per ridimensionare l'istanza di macchina virtuale. NetApp consiglia di raddoppiare l'allocazione corrente di CPU e RAM per garantire prestazioni ottimali. La tabella seguente mostra i livelli di dimensionamento consigliati, in cui ogni livello raddoppia la CPU e la RAM del livello precedente.

[cols="1,1,1"]
|===
| Livello | CPU (core o vCPU) | Memoria RAM 


| Minimo | 8 | 32 GB 


| Medio | 16 | 64 GB 


| Grande | 32 | 128 GB 
|===

== Monitorare l'agente

Rimani informato sui problemi relativi a spazio su disco, RAM e CPU sulla VM dell'agente, in modo da poterli risolvere.

La console ti avvisa quando la macchina virtuale dell'agente non è integro, compresi problemi di spazio su disco, RAM e CPU.  Monitora queste notifiche nel Centro notifiche all'interno della Console oppure configura le notifiche e-mail.  È normale che si verifichino occasionalmente aumenti dello spazio su disco, della memoria o dell'utilizzo della CPU, ma se ciò accade frequentemente, è opportuno adottare misure per risolverlo.

Ad esempio, la Console ti avvisa quando una risorsa agente (CPU, RAM o spazio su disco) supera il 90% della sua capacità totale per 30 minuti consecutivi.  Successivamente, se l'utilizzo delle risorse scende al di sotto di tale soglia, la notifica viene visualizzata come risolta (verde) nel Centro notifiche.


NOTE: Collabora con il supporto NetApp se hai domande sulla modifica della tua VM agente.

[[stop-and-start-the-agent-vm]]
== Arresta e avvia la macchina virtuale dell'agente

Limita i tempi di inattività quando arresti e avvii la VM dell'agente, perché i servizi di gestione e dati dipendono dal fatto che l'agente rimanga operativo.

Se necessario, arrestare e avviare la VM dell'agente tramite la console del provider cloud o le procedure standard in sede.

link:concept-agents.html#agents-must-be-operational-at-all-times["Tieni presente che l'agente della console deve essere sempre operativo"] .



[[connect-to-the-linux-vm]]
[[connect-linux-host]]
== Connettiti alla VM Linux

Verifica lo stato dell'agente di Console dalla sua macchina virtuale Linux per confermare che sia in esecuzione.

Se devi connetterti alla VM Linux su cui è in esecuzione l'agente, utilizza le opzioni di connettività del tuo provider cloud.

AWS:: Quando si crea l'istanza dell'agente in AWS, fornire una chiave di accesso AWS e una chiave segreta.  È possibile utilizzare questa coppia di chiavi per connettersi tramite SSH all'istanza.  Utilizzare il nome utente 'ubuntu' per l'istanza EC2 Linux.  Per gli agenti creati prima di maggio 2023, utilizzare il nome utente 'ec2-user'.
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["Documentazione AWS: connettiti alla tua istanza Linux"^]

--
Azzurro:: Quando si crea la macchina virtuale dell'agente in Azure, si specifica un nome utente e si sceglie di autenticarsi con una password o una chiave pubblica SSH.  Utilizza il metodo di autenticazione scelto per connetterti alla VM.
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Documentazione di Azure: accesso SSH alla macchina virtuale"^]

--
Google Cloud:: Non è possibile specificare un metodo di autenticazione quando si crea un agente in Google Cloud.  Tuttavia, puoi connetterti all'istanza della VM Linux tramite Google Cloud Console o Google Cloud CLI (gcloud).
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud Docs: connessione alle VM Linux"^]
