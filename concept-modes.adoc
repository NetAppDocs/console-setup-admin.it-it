= Scopri di più sulle modalità di distribuzione NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Puoi utilizzare NetApp Console tramite l'applicazione SaaS oppure installarla autonomamente nel tuo ambiente (cloud o on-premises).

NetApp si riferisce a questi casi d'uso come _modalità di distribuzione_. Ogni modalità offre connettività, funzionalità e servizi diversi per le esigenze aziendali e di sicurezza.

Modalità standard (SaaS):: L'applicazione NetApp Console SaaS (software-as-a-service) consente l'accesso a tutti i servizi dati NetApp, aggiornamenti automatici e opzioni di autenticazione flessibili come la federazione delle identità e gli accessi al sito di supporto NetApp. Questa modalità supporta gli abbonamenti al marketplace e le licenze BYOL. Questa modalità è ideale per la maggior parte degli utenti e delle organizzazioni, in particolare per coloro che desiderano il maggior numero di funzionalità e servizi disponibili con NetApp Console.
Modalità limitata (installata nel tuo cloud pubblico):: La modalità limitata è pensata per le organizzazioni che necessitano di maggiore sicurezza e connettività limitata, come governi e aziende regolamentate. Si installa la NetApp Console nel proprio cloud pubblico (in una regione governativa, sovrana o commerciale), e questa ha una connettività outbound limitata verso gli endpoint API della NetApp Console (ospitati nell'applicazione SaaS). La modalità limitata fornisce accesso ai principali servizi dati, tra cui Cloud Volumes ONTAP, Azure NetApp Files, NetApp Backup and Recovery (in regioni governative e commerciali) e classificazione dei dati, insieme ad aggiornamenti software automatizzati e federazione delle identità.
Modalità privata (installata presso la tua sede o nel cloud):: La modalità privata è pensata per le organizzazioni con esigenze di sicurezza rigorose, come quelle in AWS Secret Cloud, AWS Top Secret Cloud, Azure IL6 o in ambienti air-gapped. Non si connette all'applicazione SaaS NetApp Console o alle API NetApp basate sul cloud, offrendo il pieno controllo e bloccando le comunicazioni esterne. I servizi dati supportati includono NetApp Backup and Recovery, NetApp Data Classification, NetApp Replication e Cloud Volumes ONTAP. Tutto lo storage e l'autenticazione rimangono locali, mantenendo i dati all'interno del proprio ambiente. Utilizzare questa modalità per appaltatori della difesa, istituti finanziari con rigide regole di residenza dei dati ed enti governativi con sistemi classificati.


Quando è installato presso la vostra sede, sono supportati solo i sistemi di storage ONTAP.


NOTE: NetApp Console limita il flusso di dati in modalità riservata e privata, ma è necessario assicurarsi che l'ambiente sia conforme alle normative.

Ogni modalità di distribuzione differisce in termini di connettività in uscita, posizione, installazione, autenticazione, servizi dati e metodi di addebito.

=== Come funziona la NetApp Console in modalità standard

In modalità standard la console funziona come segue:

Comunicazione in uscita:: È richiesta la connettività da un agente all'applicazione SaaS della NetApp Console, alle risorse pubblicamente disponibili del tuo cloud provider e ad altri componenti essenziali per le operazioni quotidiane.
+
--
* link:task-install-agent-aws-console.html#networking-aws-agent["Endpoint che un agente contatta in AWS"]
* link:task-install-agent-azure-console.html#networking-azure-agent["Endpoint contattati da un agente in Azure"]
* link:task-install-agent-google-console-gcloud.html#networking-gcp-agent["Endpoint che un agente contatta in Google Cloud"]


--
Posizione supportata per un agente NetApp Console:: In modalità standard, puoi installare un agente Console nel cloud o presso la tua sede.



NOTE: L'installazione di un agente nel cloud comporta costi di utilizzo del cloud.

Aggiornamenti dell'agente della console:: NetApp aggiorna automaticamente il software dell'agente ogni mese.
Accesso all'interfaccia utente:: Accedi all'interfaccia utente dall'applicazione Console SaaS, che è disponibile tramite Internet pubblico.
Punto finale dell'API:: Le chiamate API vengono effettuate al seguente endpoint: \ https://api.bluexp.netapp.com
Autenticazione:: NetApp Console fornisce l'autenticazione tramite auth0 o NetApp Support Site (NSS) logins. È disponibile la federazione delle identità.

== NetApp Console in modalità limitata (installata nel tuo cloud pubblico)

Si installa un agente Console nel cloud (in una regione governativa, sovrana o commerciale) e dispone di una connettività outbound limitata agli endpoint API della NetApp Console (ospitati nell'applicazione SaaS).

Gli utenti accedono all'interfaccia utente locale fornita dall'agente della Console, non all'applicazione SaaS.

A seconda dei servizi dati e delle funzionalità che intendi utilizzare, un amministratore dell'organizzazione Console crea ulteriori agenti Console per gestire i dati all'interno del tuo ambiente cloud ibrido.

<<Modalità limitata,Scopri di più sulla connettività outbound alle API della NetApp Console>>.

=== Come funziona la NetApp Console in modalità limitata

La console funziona come segue in modalità limitata:

Comunicazione in uscita:: Un agente richiede connettività outbound alle API basate sul cloud di NetApp per il supporto dei servizi dati, degli aggiornamenti software, dell'autenticazione e della trasmissione dei metadati.
+
--
NetApp non avvia la comunicazione con un agente. L'agente avvia tutte le comunicazioni e può estrarre o inviare dati da o verso le API e i servizi NetApp secondo necessità.

È inoltre richiesta una connessione alle risorse del provider cloud all'interno della regione.

--
Posizione supportata per un agente:: In modalità limitata, installi agenti nel cloud: in una regione governativa, sovrana o commerciale.
Aggiornamenti dell'agente della console:: NetApp Console aggiorna automaticamente il software dell'agente ogni mese.
Accesso all'interfaccia utente:: Gli utenti accedono alla Console da una macchina virtuale agente distribuita nella tua cloud region.
Punto finale dell'API:: Le chiamate API vengono effettuate a una macchina virtuale agente.
Autenticazione:: L'autenticazione viene fornita tramite il servizio cloud di NetApp Console utilizzando auth0. È disponibile anche la federazione delle identità.




=== Come iniziare con la modalità limitata

È necessario abilitare la modalità con restrizioni quando si crea il proprio account NetApp Console. Se non si dispone di un'organizzazione, al primo accesso all'agente Console installato viene richiesto di crearne una e di abilitare la modalità con restrizioni.

Si noti che l'impostazione della modalità con restrizioni è fissa dopo la creazione dell'organizzazione. Non è possibile abilitare o disabilitare la modalità con restrizioni in un secondo momento. link:task-quick-start-restricted-mode.html["Scopri come iniziare con la modalità limitata"].

=== Come funziona NetApp Console in modalità privata

NetApp Console funziona come segue in modalità privata:

Comunicazione in uscita:: Non è richiesta alcuna connettività outbound all'applicazione SaaS della Console (dove risiedono endpoint API aggiuntivi). Tutti i pacchetti, le dipendenze e i componenti essenziali sono inclusi nell'agente della Console e forniti dalla macchina locale. La connettività alle risorse pubblicamente disponibili del tuo cloud provider è richiesta solo se stai distribuendo Cloud Volumes ONTAP.
Posizione supportata per l'agente della NetApp Console:: In modalità privata, l'agente Console è supportato nel cloud o on-premises.
Aggiornamenti dell'agente della console:: È necessario aggiornare manualmente il software dell'agente della Console. NetApp pubblica il software dell'agente della Console sul NetApp Support Site a intervalli non definiti.
Accesso all'interfaccia utente:: Gli utenti accedono alla Console dall'agente Console distribuito nella tua regione cloud o on-premises.
Punto finale dell'API:: Le chiamate API vengono effettuate alla macchina virtuale dell'agente NetApp Console.
Autenticazione:: L'autenticazione avviene tramite la gestione e l'accesso degli utenti locali. L'autenticazione non avviene tramite il servizio cloud della NetApp Console.
