= Scopri di più sugli agenti NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Un agente Console è un componente software leggero che si installa nella rete per connettere l'infrastruttura di storage alla NetApp Console. Consente l'orchestrazione avanzata dello storage, i servizi dati e l'integrazione sicura con il cloud.



== Cosa fa un agente Console

Un agente Console colma il divario di connettività tra i sistemi di storage e NetApp Console. Collega in modo sicuro l'infrastruttura alle NetApp API e a Console, consentendo di:

* Scopri e monitora i sistemi di archiviazione su AWS, Azure, Google Cloud e negli ambienti locali dalla NetApp Console.
* Orchestrare le attività di provisioning e configurazione dello storage sui sistemi di storage dalla NetApp Console.
* Utilizza flussi di lavoro intelligenti per la protezione e la gestione dei dati.
* Monitora in modo sicuro l'utilizzo dei servizi cloud e collega le implementazioni all'abbonamento corretto per una fatturazione e una gestione dei costi accurate.




=== Architettura dell'agente della console

Gli agenti operano con processi leggeri che:

* Prelevare o inviare dati da e verso l'applicazione SaaS NetApp Console (modalità standard e con restrizioni)
* Avvia tutte le comunicazioni: la Console non avvia mai chiamate outbound agli agenti
* Connettiti ai tuoi sistemi di storage utilizzando protocolli di gestione standard
* Utilizzare TLS 1.3 per comunicazioni sicure con i cloud provider e le API della NetApp Console




=== Disponibilità dell'agente della console e requisiti operativi

Gli agenti della console sono fondamentali per NetApp Console. Gli agenti devono rimanere operativi e raggiungibili per garantire servizi di gestione e dati ininterrotti. È tua responsabilità garantire:

* Gli agenti rimangono attivi e funzionanti
* Gli agenti hanno connettività di rete agli endpoint richiesti
* I guasti infrastrutturali vengono risolti rapidamente
* Le VM degli agenti vengono mantenute e aggiornate secondo le raccomandazioni di NetApp




== Quando hai bisogno di un agente Console

È necessario distribuire almeno un agente Console quando si desidera:

* Utilizzare modalità di distribuzione limitate o private (Console installata nel proprio ambiente). Potrebbero essere necessari agenti aggiuntivi per abilitare alcuni servizi.
* Accedi a servizi dati avanzati (NetApp Backup and Recovery, NetApp Disaster Recovery, NetApp Ransomware Resilience, NetApp Data Classification e altro ancora).
* Gestisci i sistemi Cloud Volumes ONTAP.
* Eseguire attività di gestione avanzate sui cluster ONTAP locali.
* Tieni traccia delle licenze, monitora lo stato di integrità dello storage e pianifica gli aggiornamenti del ciclo di vita.


Senza un agente, puoi eseguire l'individuazione di base dello storage e accedere a un set limitato di funzionalità di monitoraggio e gestione dello storage. Tuttavia, la maggior parte dei casi d'uso enterprise richiede uno o più agenti operativi.

== Opzioni di deployment per gli agenti della Console

È possibile distribuire gli agenti della Console in:

* Servizi Web Amazon
* Microsoft Azure
* Google Cloud
+
Per gestire le risorse di Google Cloud, è necessario distribuire l'agente in Google Cloud. Un agente locale non può gestire le risorse di Google Cloud.

* Presso la vostra sede (solo modalità standard o privata)


La modalità di distribuzione della Console, l'ambiente di storage e le esigenze di sovranità dei dati determinano dove distribuire gli agenti. Distribuire più agenti in diversi ambienti per la separazione organizzativa o per esigenze aziendali.

È possibile distribuire gli agenti direttamente dalla Console, dal marketplace cloud oppure manualmente in vCenter o in locale. link:concept-agent-install-options.html["Confronta i metodi di implementazione per scegliere quello più adatto al tuo ambiente"].



=== Agenti per l'applicazione NetApp Console SaaS (modalità standard)

Distribuisci agenti nel tuo cloud o on-premises per collegare la connettività all'applicazione SaaS della Console ospitata nel cloud. Gli agenti abilitano funzionalità avanzate mentre l'interfaccia utente della Console rimane accessibile da qualsiasi luogo.

È possibile installare gli agenti direttamente dalla Console quando si utilizza l'applicazione SaaS (modalità standard). È possibile installare in AWS, Azure o Google Cloud, oppure manualmente in sede sul proprio host Linux o nel proprio ambiente VCenter.



=== Agenti per NetApp Console in modalità limitata

In modalità limitata, gli utenti accedono alla NetApp Console direttamente da un agente installato, non dall'applicazione SaaS ospitata nel cloud. È necessario installare almeno un agente che funga da punto di accesso alla Console. Ulteriori agenti sono necessari per abilitare i servizi dati e gestire i sistemi di archiviazione.

Installa gli agenti dal marketplace del tuo cloud provider oppure installa manualmente il software sul tuo host Linux nel cloud, in locale o nel tuo ambiente VCenter.



=== Agenti per NetApp Console in modalità privata (in locale o nel cloud senza connettività outbound)

In modalità privata, gli utenti accedono alla NetApp Console direttamente da un agente installato. È necessario installare almeno un agente che funga da punto di accesso alla Console. Ulteriori agenti sono necessari per abilitare i servizi dati e gestire i sistemi di archiviazione.

Installa gli agenti nel tuo data center o in un ambiente isolato dalla rete. Gli agenti non hanno connettività con gli endpoint API di NetApp e tutte le operazioni rimangono locali, con piena sovranità dei dati e controllo.



=== Usa più agenti quando necessario

Ogni agente opera in modo indipendente e può gestire più sistemi di storage e servizi dati. Distribuire più agenti quando è necessario:

* Isolamento per tipo di storage o funzione organizzativa
* Requisiti di segmentazione geografica o di rete


Per esempio:

* In un ambiente multicloud, è possibile distribuire un agente in AWS e un altro in Azure. Ciascun agente gestisce i sistemi Cloud Volumes ONTAP nel rispettivo ambiente.
* Un service provider potrebbe utilizzare un'organizzazione Console per fornire servizi ai clienti e un'altra organizzazione per il disaster recovery di un'unità aziendale. Ogni organizzazione necessita di un proprio agente.




== Aggiornamenti dell'agente della console

Gli agenti nel cloud si aggiornano automaticamente quando dispongono di accesso a Internet outbound. Per gli agenti senza accesso a Internet (modalità privata), consultare link:task-upgrade-agent.html["Gestisci gli aggiornamenti degli agenti della console"] per le istruzioni sull'aggiornamento manuale.
